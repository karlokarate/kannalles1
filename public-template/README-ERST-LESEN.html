KH Checker

Die fertige PWA funktioniert auf einem HTTPS-Host ohne eigenen App-Server: Standardmäßig fragt der Browser die offiziellen OFF-Dienste direkt ab. Ein Daten-Gateway ist eine optionale zweite Lane.

Aktuellen Source bauen: Alte Release-ZIPs sind keine Deployment-Fallbacks. Der Workflow erzeugt das Artefakt reproduzierbar aus dem eingecheckten Source- und Lockfile-Stand.

Deployment über GitHub Actions

  1. Den aktuellen Source-Stand inklusive Lockfile einchecken.
  2. Unter Actions den Workflow Build and deploy KH Checker to Pages ohne Eingaben starten.
  3. Der Workflow installiert das Lockfile, baut die PWA und veröffentlicht das neue Artefakt.
  4. Nach erfolgreichem Lauf die vom Workflow ausgegebene Pages-Adresse öffnen.

Was auf dem Gerät läuft

Zwei API-Lanes

Ohne Gateway nutzt der Browser Search-a-licious mit OFF Legacy als Reserve. Eine konfigurierte Gateway-URL übernimmt die gesamte Anfrage autoritativ.

Lokaler Cache

Fresh-/Stale-Cache, Request-Deduplizierung, Kalibrierungen, Verlauf und Berechnung laufen lokal in der PWA.

Gezielte Details

Nur das ausgewählte Barcode-Produkt wird über OFF API v3.6 geladen. v2 ergänzt nur weiterhin fehlende Nährwerte.

Optionales OFF-Konto

Unter Einstellungen kann ein persönliches OFF-Konto geprüft und lokal gespeichert werden. Es wird ausschließlich bei direkten OFF-Anfragen verwendet, nie bei Search-a-licious oder einem Gateway.

Kontrollierte Fehler

Kein lokaler Cooldown: technische Details bleiben sichtbar und ein manueller Retry ist sofort möglich.

Installation

  • iPhone/iPad: Pages-Seite in Safari öffnen → Teilen → Zum Home-Bildschirm.
  • Android: Pages-Seite in Chrome öffnen → App installieren.
  • Desktop: Installationssymbol eines PWA-fähigen Browsers verwenden.
Nicht per file:// betreiben: Service Worker und PWA-Installation benötigen einen sicheren HTTP(S)-Kontext. GitHub Pages stellt ihn bereit.

API auf dem Zielgerät prüfen

API-DIAGNOSE.html testet die aktive direkte oder Gateway-Lane sowie die einzelnen Such- und Produktpfade. Fehler, Endpunkt, Status und Laufzeit werden angezeigt.

Datenschutzgrenze

Im Direktbetrieb erhalten Search-a-licious beziehungsweise OFF den Suchbegriff oder Barcode und die öffentliche IP-Adresse. Bei ausdrücklich verbundenem OFF-Konto speichert das Browserprofil zusätzlich Benutzername und Passwort lokal und sendet sie nur an world.openfoodfacts.org. Produktbilder kommen von images.openfoodfacts.org. Offline verfügbar sind nur bereits gecachte App-Assets, Bilder und Daten.

Validierung

Der Release-Gate umfasst Vitest, TypeScript, Biome, Playwright auf Chromium, Firefox und WebKit, axe-core, npm audit, Service-Worker-/Manifest-Prüfung, mobile Unterpfade, sichere ZIP-Extraktion und vollständige SHA-256-Prüfsummen.

Gesundheitshinweis: Open-Food-Facts-Daten können unvollständig oder falsch sein. Etikett prüfen und das Ergebnis nicht ungeprüft für Therapie- oder Insulindosierungsentscheidungen verwenden.
